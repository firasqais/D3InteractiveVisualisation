Interaction and transitions

Here is the secret of interactive D3: interaction is just running the data join again with new data. Sorting is new order, same join. Filtering is fewer items, so some bars exit. Hover a bar for details on demand.

The update function

Every button builds a new array (sorted or filtered) and calls update(rows). That's the whole trick.

function update(rows) {
  x.domain(rows.map(d => d.store));
  const t = svg.transition().duration(750).ease(d3.easeCubic);

  g.selectAll("rect.bar")
    .data(rows, d => d.store)              // key: each store keeps its own bar
    .join(
      enter => enter.append("rect")
          .attr("class", "bar")
          .attr("x", d => x(d.store))
          .attr("y", h).attr("height", 0)  // start flat on the baseline…
          .attr("fill", d => colour(d.region)),
      update => update,
      exit => exit.transition(t)
          .attr("y", h).attr("height", 0)  // …and leave the same way
          .remove()
    )
    .transition(t)                         // enter + update move together
      .attr("x", d => x(d.store))
      .attr("width", x.bandwidth())
      .attr("y", d => y(d.revenue))
      .attr("height", d => h - y(d.revenue));

  xAxis.transition(t).call(d3.axisBottom(x));
}

Try this

  1. Revenue ▼: the bars glide to their new places. Because of the key, you can follow each store as it moves. Bostock (2012) calls this object constancy.
  2. Region GCC: nine bars exit, three remain and widen. Back to All.
  3. Set Key to none (index) and sort again: the bars stay put and morph into other stores. You can't tell who went where.
  4. Set 2000 ms and easeBounceOut: fun, but it's a show, not an explanation. Keep transitions to about 250–750 ms (Heer & Robertson, 2007).
